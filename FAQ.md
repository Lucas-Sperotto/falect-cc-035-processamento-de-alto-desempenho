# Perguntas Frequentes

## Faço um fork por atividade?

Não. Faça um único fork deste repositório e crie uma branch para cada atividade.

## Posso desenvolver na `main`?

Não. A `main` deve acompanhar o repositório oficial. Sincronize-a e crie uma branch `atividade/...` ou `projeto/...`.

## O `git merge --ff-only upstream/main` falhou. O que faço?

Não force a operação. Execute `git status`, copie a mensagem completa e peça orientação antes de usar `reset`, `rebase` ou `push --force`.

## Toda atividade exige Pull Request?

Não. O enunciado informa se a entrega será por branch, commit, Pull Request ou outro canal. Quando houver Pull Request público, não inclua dados pessoais ou respostas que o enunciado determine manter privadas.

## A nota é lançada pelo GitHub?

Não. O GitHub registra o processo e a entrega técnica. O SIGAA é o ambiente oficial para prazos, envio formal e notas.

## Posso usar IA?

Somente nas atividades marcadas **IA permitida**, dentro dos limites do enunciado e da [política de IA](POLITICA_IA.md).

## Preciso ter uma GPU NVIDIA?

Não para iniciar a disciplina. Atividades de CUDA dependerão da infraestrutura disponível, e o professor indicará alternativa quando o equipamento do estudante não for compatível.

## Posso publicar o diagnóstico do meu computador?

Não. O arquivo `diagnostico-ambiente-pad.txt` deve ser enviado apenas pelo canal indicado e está ignorado pelo Git. Revise o conteúdo para evitar dados pessoais mesmo no SIGAA.

## Preciso comentar todas as linhas?

Não. Prefira nomes claros, funções coesas e comentários que expliquem decisões, hipóteses ou trechos não óbvios.

## Como pedir ajuda?

Informe:

- atividade e objetivo;
- comando de compilação ou execução;
- mensagem de erro completa;
- entrada, saída esperada e saída observada;
- tentativas já realizadas.

Remova e-mail, usuário, caminhos pessoais, tokens e outras informações sensíveis antes de publicar.
